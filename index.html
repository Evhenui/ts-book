1. Основи типів

TypeScript = JavaScript + перевірка типів до запуску. Після компіляції типи зникають, у браузері лишається звичайний JS. Тип — це як props з валідацією в Vue: каже, що саме сюди можна передати.

Анотації та inference

let age: number = 30;      // явно
let name = "Євген";        // TS сам зрозумів: string
age = "тридцять";          // ❌ помилка ще в редакторі
Правило: коли TS сам бачить тип (як у name), анотацію не пиши. Пиши її там, де TS не здогадається: параметри функцій, порожні масиви, дані ззовні.

Основні типи

let ok: boolean = true;
let nothing: null = null;
let list: number[] = [1, 2, 3];          // те саме що Array<number>
let pair: [string, number] = ["age", 30]; // кортеж: рівно 2 елементи, у цьому порядку

any, unknown, never

let a: any = "hi";       // "вимкни перевірку". Небезпечно!
a.foo.bar();             // TS мовчить, а в браузері впаде

let u: unknown = "hi";   // "не знаю що це, спочатку перевір"
u.toUpperCase();         // ❌ не можна одразу
if (typeof u === "string") u.toUpperCase();  // ✅ після перевірки можна

function fail(msg: string): never { throw new Error(msg); } // ніколи не повертається
any заражає код: де зʼявився, там TS більше не допомагає. Не знаєш тип? Бери unknown.

Питання

  1. Що станеться з типами після компіляції?
    ПоказатиЗникнуть. У браузер іде чистий JS, а типи існують тільки під час написання коду.
  2. Чим unknown безпечніший за any?
    ПоказатиЗ unknown нічого не можна робити, поки не перевіриш тип. З any можна все, навіть те, що впаде.
  3. Коли тип можна не писати?
    ПоказатиКоли TS бачить його сам зі значення (let n = 5). Пишемо там, де значення ще немає або воно приходить ззовні.

Задачки

  1. Опиши змінну coords: кортеж з двох чисел (широта, довгота).
    Підказкаlet coords: [number, number] = [46.48, 30.72];
  2. Функція parse(data: unknown) має повернути довжину, якщо data рядок, і 0 в інших випадках.
    Підказкаreturn typeof data === "string" ? data.length : 0;

2. Обʼєкти: interface і type

Обʼєкт у TS описується формою: які поля і якого типу. Це як опис props компонента.

interface User {
  id: number;
  name: string;
  email?: string;        // ? = поле необовʼязкове
  readonly createdAt: Date; // readonly = після створення не змінюй
}

const u: User = { id: 1, name: "Євген", createdAt: new Date() };
u.createdAt = new Date(); // ❌ readonly
u.email.length;           // ❌ email може бути undefined

interface чи type?

type Id = string | number;       // type вміє й не-обʼєкти (union, кортежі)
interface Admin extends User {   // interface зручно розширювати
  role: "admin";
}
Для обʼєктів практично однаково. Проста порада: interface для форми обʼєкта, type для всього іншого (union, кортежі, складні типи). Головне, щоб у команді було одне правило.

Словник довільних ключів

const prices: Record<string, number> = { apple: 10, pear: 15 };
// те саме: { [key: string]: number }

Питання

  1. Що означає ? після імені поля?
    ПоказатиПоле необовʼязкове: його тип стає T | undefined, тому перед використанням TS вимагає перевірку.
  2. Для чого readonly?
    ПоказатиЗабороняє перезаписувати поле після створення. Перевірка тільки на етапі написання коду.
  3. Яка головна різниця між interface і type?
    Показатиtype може описати не лише обʼєкти (union, кортежі). interface зручно розширюється через extends. Для обʼєктів різниця мінімальна.

Задачки

  1. Опиши Product: id (число), title (рядок), price (число), description (необовʼязково).
    Підказкаinterface Product { id: number; title: string; price: number; description?: string }
  2. Зроби Cart, де ключ це id товару (рядок), а значення це кількість (число).
    Підказкаtype Cart = Record<string, number>;

3. Функції

У функції TS типізує вхід (параметри) і вихід (що повертає).

function add(a: number, b: number): number {
  return a + b;
}

const greet = (name: string, title?: string): string =>
  title ? `${title} ${name}` : name;

function log(msg: string, level = "info"): void {  // void = нічого не повертає
  console.log(level, msg);
}
Тип повернення часто можна не писати, TS виведе сам. Але для публічних функцій корисно писати його явно: випадково змінити "контракт" буде важче.

Функція як тип (колбеки)

type Handler = (value: string) => void;   // як @input або emit у Vue

function onChange(cb: Handler) { cb("hello"); }
onChange((v) => console.log(v.toUpperCase())); // v автоматично string

Перевантаження (overloads)

function format(x: string): string;
function format(x: number): string;
function format(x: string | number): string { return String(x); }
Перевантаження потрібні рідко. Часто простіше написати union (string | number), як у прикладі вище.

Питання

  1. Що означає void?
    ПоказатиФункція нічого корисного не повертає (як обробник кліку).
  2. Чому в onChange((v) => ...) не треба писати тип v?
    ПоказатиTS бере його з типу Handler. Це contextual typing: тип параметра береться з місця, куди передають функцію.
  3. Чим title?: string відрізняється від level = "info"?
    ПоказатиОбидва необовʼязкові. Але title може бути undefined всередині, а level має значення за замовчуванням, тож завжди рядок.

Задачки

  1. Напиши тип Predicate: функція, що приймає число і повертає boolean. Потім зроби isEven цього типу.
    Підказкаtype Predicate = (n: number) => boolean; const isEven: Predicate = (n) => n % 2 === 0;
  2. Типізуй function filterBy(items, fn): items це масив чисел, fn це Predicate, результат це масив чисел.
    Підказкаfunction filterBy(items: number[], fn: Predicate): number[] { return items.filter(fn); }

4. Union і narrowing

Union це "або те, або те". Narrowing це коли TS після твоєї перевірки розуміє, який саме варіант зараз перед ним.

type Status = "loading" | "success" | "error"; // тільки ці 3 рядки, як enum

function show(id: string | number) {
  if (typeof id === "string") id.toUpperCase(); // тут TS знає: string
  else id.toFixed(2);                           // а тут: number
}

Discriminated union: найкорисніший патерн

Це стан запиту, який ти пишеш у кожному Vue/React-компоненті. Кожен варіант має спільне поле-мітку (status).

type Result =
  | { status: "success"; data: string[] }
  | { status: "error"; message: string };

function render(r: Result) {
  if (r.status === "success") return r.data.length; // є data
  return r.message;                                 // тут лише error
}
Чим ще можна звузити: typeof x, x === "a", "key" in obj, x instanceof Date, проста перевірка if (x).

Питання

  1. Що таке narrowing?
    ПоказатиTS звужує широкий тип (string | number) до конкретного всередині перевірки.
  2. Навіщо в discriminated union спільне поле status?
    ПоказатиЗа ним TS розрізняє варіанти. Перевірив status === "error", і TS дозволяє брати message, але не data.
  3. Чим літеральний тип "a" | "b" кращий за просто string?
    ПоказатиРедактор підкаже допустимі значення, а друкарську помилку ("sucess") TS зловить одразу.

Задачки

  1. Опиши Shape: коло (kind: "circle", radius) або квадрат (kind: "square", side). Напиши area(s: Shape).
    Підказкаif (s.kind === "circle") return Math.PI * s.radius ** 2; return s.side ** 2;
  2. Функція len(x: string | string[]) повертає довжину рядка або кількість елементів.
    ПідказкаІ в рядка, і в масиву є .length, тож перевірка тут не потрібна. А якщо хочеш різну логіку, використай Array.isArray(x).

5. Generics

Generic це тип із "параметром". Як функція приймає значення, так generic приймає тип. Ти вже бачив це: Promise<User>, Array<number>, AuthRequest<P> із бекенду, ref<string>() у Vue.

function first<T>(arr: T[]): T | undefined {
  return arr[0];
}
first([1, 2, 3]);      // T = number
first(["a", "b"]);     // T = string

interface ApiResponse<T> {
  data: T;
  error?: string;
}
const res: ApiResponse<User[]> = { data: [] };

Обмеження: extends

function byId<T extends { id: number }>(items: T[], id: number) {
  return items.find((i) => i.id === id); // можна, бо в T точно є id
}
T це просто змінна для типу. Названа так за традицією. Може бути й Item, якщо так зрозуміліше.
Не роби generic там, де він не потрібен. Якщо тип використовується в функції один раз, звичайний тип простіший.

Питання

  1. Навіщо generics, якщо є any?
    Показатиany губить звʼязок між входом і виходом. Generic його зберігає: поклав number[], отримав number.
  2. Що робить T extends { id: number }?
    ПоказатиОбмежує T: підходять лише типи, у яких є id: number. Тому всередині можна безпечно читати .id.
  3. Як зрозуміти запис Promise<User[]>?
    Показати"Обіцянка, яка колись видасть масив користувачів". У кутових дужках лежить тип результату.

Задачки

  1. Напиши last<T>(arr: T[]), що повертає останній елемент.
    Підказкаfunction last<T>(arr: T[]): T | undefined { return arr[arr.length - 1]; }
  2. Опиши Paginated<T>: items: T[], total: number, page: number.
    Підказкаinterface Paginated<T> { items: T[]; total: number; page: number }

6. Utility types

Готові "перетворювачі" типів у самому TS. Беруть твій тип і роблять з нього новий, щоб не переписувати його вручну.

interface User { id: number; name: string; email: string; password: string }

type UserUpdate = Partial<User>;              // усі поля стають необовʼязковими
type UserCard   = Pick<User, "id" | "name">;   // лише ці поля
type PublicUser = Omit<User, "password">;      // усе, крім password
type Frozen     = Readonly<User>;              // усі поля readonly
type Roles      = Record<"admin" | "user", string[]>;
type Out        = ReturnType<typeof fetchUser>; // що повертає функція
UtilityДе знадобиться
Partialформа редагування, PATCH-запит
Omitвідповідь API без пароля (як у бекенді)
Pickкартка в списку з кількома полями
Recordсловники, довідники

Питання

  1. Навіщо Omit<User, "password">, якщо можна описати новий тип?
    ПоказатиНовий тип треба підтримувати окремо: додав поле в User, а там забув. Omit оновлюється сам.
  2. Чим Pick відрізняється від Omit?
    ПоказатиPick каже "залиш тільки ці поля", Omit каже "прибери ці".
  3. Який utility зручний для PATCH?
    ПоказатиPartial: клієнт може надіслати лише змінені поля.

Задачки

  1. Для Product з розділу 2 зроби NewProduct без id (його видає база).
    Підказкаtype NewProduct = Omit<Product, "id">;
  2. Зроби ProductPatch, де всі поля необовʼязкові, крім id.
    Підказкаtype ProductPatch = Partial<Omit<Product, "id">> & Pick<Product, "id">; Символ & зʼєднує два типи в один.
